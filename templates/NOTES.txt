REMINDERS
=========

1. Generate runtime secrets and pass them in. The installer's generate-secrets.sh
   gives you the right shape:

     openssl rand -base64 32   # API_JWT_SECRET, API_JWT_REFRESH_SECRET, NEXTAUTH_SECRET
     openssl rand -hex 32      # API_CRYPTO_KEY, CODE_MANAGEMENT_SECRET, API_MCP_MANAGER_ENCRYPTION_SECRET

   Then:
     helm upgrade {{ .Release.Name }} . \
       --set secrets.API_JWT_SECRET=... \
       --set secrets.API_JWT_REFRESH_SECRET=... \
       --set secrets.API_CRYPTO_KEY=... \
       --set secrets.WEB_NEXTAUTH_SECRET=... \
       --set secrets.NEXTAUTH_SECRET=... \
       --set secrets.CODE_MANAGEMENT_SECRET=...

2. Set NEXTAUTH_URL to whatever URL the browser will hit (your ingress host).
   Mismatch here = login loops.

3. At least one Git provider webhook (GitHub/GitLab/Bitbucket/Azure/Forgejo) must
   be configured in `config.API_*_CODE_MANAGEMENT_WEBHOOK` for code review to fire.

4. RabbitMQ: the default image (rabbitmq:4.2.2-management) does NOT include the
   `rabbitmq_delayed_message_exchange` plugin that kodus-installer's reference
   image ships. If you depend on it, build a custom image (see
   kodus-installer/docker/rabbitmq/Dockerfile) and override `rabbitmq.image`.
